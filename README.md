# QuietPeer · P2P 加密聊天室

双人、纯文本、浏览器端点间 WebRTC DataChannel。Node服务只转发连接信令，不转发聊天正文。没有账号、数据库或聊天记录持久化。此版本仅用于本地开发与验收，没有公网部署。

## 环境与安装

需要 Node.js 22.12+，建议使用本次验收的 Node 24；npm固定为11.6.2，依赖由package-lock.json锁定。运行以下命令不会使用生产凭证：

```bash
npm ci
PORT=3000 npm run dev
```

浏览器打开 `http://127.0.0.1:3000`。服务只监听127.0.0.1，跨机器不能访问；不要把localhost链接发给异地用户并声称能加入。Owner指定的本地预览使用由会话配置声明的端口；普通解压项目用上述3000。若端口被占用服务会失败，不自动换端口。

本地构建运行：

```bash
npm run build
PORT=3000 npm start
```

只进行本机loopback验证可用HTTP安全上下文；未来若授权跨机器部署，必须使用受信任HTTPS/WSS、重新设置Origin及网络穿透，并重新验收。当前没有STUN/TURN依赖，只支持当前网络可直连的本地双浏览器场景，不承诺任意NAT可达。

## 使用

在浏览器A创建房间，复制邀请。在另一个独立浏览器或独立配置上下文B粘贴邀请并加入。等待双方实际DataChannel连接建立。邀请是加入能力，不是身份证明；不要公开分享。邀请只允许一位加入者，等待加入有效期10分钟。

**请通过独立可信渠道核对完整指纹。**将A显示的“本地证书指纹”通过当面、可信通话或已有可信渠道交给B；B反向提供自己的本地指纹。每端把从该渠道收到的对方全长SHA-256指纹填入“对方带外指纹”，并确认它与页面上“对方实际证书指纹”一致。双方都完成确认才开放聊天。不要在本聊天室、同一信令服务或未认证的链接里交换指纹来声称完成带外认证。

输入指纹不匹配或点击“指纹不一致”会终止连接。这里认证的是本次DTLS证书端点，不是现实法律身份。网页按钮只能记录你的核对动作，不能自动证明你使用了可信渠道。

“已送达”表示本次接收端已校验并收取该消息，**不表示已读**。本地send接受后只显示等待确认；ACK超时显示“送达未知”，不能断言对方没收到。正文上限4KiB UTF-8，整帧8KiB，会话消息和缓冲有界。异常帧拒绝，重复帧不重复显示；旧会话帧不继承。

结束会话会清空本端内存记录。刷新丢失记录和验证；新会话生成新证书并必须重新核对。无法恢复时明确失败，不自动跨会话重发。复制邀请到系统剪贴板可能留下本地痕迹，应用无法替你安全清空整个系统历史。

## 测试

```bash
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
```

Playwright自动启动独立loopback测试服务，使用两个独立browser contexts建立**真实WebRTC连接**，不是Mock。测试模式有受限证据入口；普通构建不包含`window.__quietpeerTest`。默认E2E测试端口5187，可用`TEST_PORT`覆盖。`TEST_ATTEMPT`改变结果目录，失败结果应保留，禁止将失败覆盖为通过。截图仅合成消息且邀请被遮盖。

测试截图/JSON等写入上一级`.work`以避免源包带缓存。可用`EVIDENCE_DIR`改变截图位置。若为项目单独保存浏览器，用`PLAYWRIGHT_BROWSERS_PATH`在安装和运行时设置同一个绝对路径。

完整结果见 `FINAL_ACCEPTANCE.md` 与 `docs/TEST_REPORT.md`；安全边界见 `SECURITY.md`。未实际运行的属性必须为NOT_TESTED/PARTIAL，底层记录篡改测试不能用合法端点改明文再加密冒充。

## 项目结构

`src/core`是实际证书绑定与聊天状态机，`src/App.tsx`和`src/styles.css`为产品界面，`server`为HTTP及信令，`shared`为信令schema，`tests`为单元/集成/E2E。没有数据库和账号代码。`plan.md`和`TODO.md`记录实施范围。

版本同步属于Owner选择的Manus管理项目，不等于公网发布。交付ZIP排除平台私有管理目录、node_modules、缓存、dist、运行日志、邀请凭据和任何私钥。
